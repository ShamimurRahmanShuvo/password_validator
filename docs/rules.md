# Password Validation Rules

The policy validation engine evaluates a sequence of `Rule` objects. Each rule receives a password and returns a `RuleResult`.

## Rule contract

The base abstraction is:

```python
from password_validator.rules.base import Rule
```

A rule must implement:

```python
def validate(self, password: str) -> RuleResult:
    ...
```

The rule should return a `RuleResult` containing:

- `passed: bool`
- `rule_name: str`
- `message: str | None`
- `code: str | None`
- `metadata: dict | None`

The base class provides convenience methods:

```python
self._passed(...)
self._failed(...)
```

## Built-in policy rules

### LengthRule

Validates minimum and maximum password length.

```python
LengthRule(min_length=8, max_length=64)
```

Failure codes include:

- `PASSWORD_TOO_SHORT`
- `PASSWORD_TOO_LONG`

### UppercaseRule

Requires at least one uppercase character.

Failure code:

```text
PASSWORD_MISSING_UPPERCASE
```

### LowercaseRule

Requires at least one lowercase character.

Failure code:

```text
PASSWORD_MISSING_LOWERCASE
```

### DigitsRule

Requires at least one numeric digit.

Failure code:

```text
PASSWORD_MISSING_DIGIT
```

### SpecialCharacterRule

Requires at least one character from the configured special-character set.

```python
SpecialCharacterRule(special_characters="!@#$%^&*")
```

Failure code:

```text
PASSWORD_MISSING_SPECIAL
```

## Default validator rule construction

When no explicit `rules` sequence is passed to `PasswordValidator`, the validator constructs its default rule set from `PasswordRuleConfig`.

The current implementation adds:

1. `LengthRule`
2. `UppercaseRule` when `require_uppercase=True`
3. `LowercaseRule` when `require_lowercase=True`
4. `DigitsRule` when `require_digit=True`
5. `SpecialCharacterRule` when `require_special=True`

The rules are evaluated in that order.

## Custom rules

A custom rule can inherit from `Rule`:

```python
from password_validator.rules.base import Rule, RuleResult


class NoUsernameRule(Rule):
    name = "no_username"

    def __init__(self, username: str):
        self.username = username

    def validate(self, password: str) -> RuleResult:
        if self.username.lower() in password.lower():
            return self._failed(
                message="Password must not contain the username",
                code="USERNAME_IN_PASSWORD",
            )

        return self._passed(
            message="Password does not contain the username"
        )
```

Use it directly:

```python
validator = PasswordValidator(
    rules=[NoUsernameRule("shuvo")]
)
```

When `rules` is explicitly supplied, those rules replace the validator's default rule construction. If you want both built-in and custom rules, create the desired sequence explicitly.

## RuleRegistry

`RuleRegistry` provides a small registration API:

```python
from password_validator.rules.registry import RuleRegistry

registry = RuleRegistry()
registry.register(NoUsernameRule("shuvo"))

rules = registry.get_rules()
```

Available operations:

- `register(rule)` — add a rule
- `unregister(rule_type)` — remove rules whose `name` matches the supplied value
- `get_rules()` — return a copy of the registered rule list
- `clear()` — remove all rules

The helper `create_default_registry(config)` creates a registry containing the standard built-in policy rules.

## Rule design principles

Rules should:

- have one clear validation responsibility;
- receive configuration through their constructor;
- return a `RuleResult`;
- avoid reading environment variables directly;
- avoid modifying other rules;
- avoid storing the password;
- avoid calculating the overall strength score.

Configuration belongs in the configuration layer. Pattern analysis belongs in the strength subsystem.

## Available rule and error identifiers

The `Rule` enum contains identifiers for current and planned/extended rule categories, including:

```text
length
uppercase
lowercase
digit
special
whitespace
repeated
sequential
blacklist
common_passwords
dictionary
regex
username
entropy
history
```

The presence of an enum value does not by itself mean that a corresponding built-in policy rule is currently implemented. The built-in policy rules are the five classes described above.

## Error codes

Current error-code definitions include codes for length, character requirements, whitespace, repeated/sequential patterns, dictionary/common passwords, regex, username, entropy, history, and blacklist scenarios.

Only the codes used by the currently implemented policy rules should be assumed to be generated by the default `PasswordValidator` rule set.
